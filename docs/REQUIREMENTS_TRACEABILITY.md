# Соответствие техническому заданию

Основание: трехстраничный PDF «Финальный проект ИИ агент». Дополнения пользователя: Telegram, discovery, итеративное согласование реализации, DeepSeek, README и отчет о применении ИИ при разработке.

| Требование | Реализация | Граница проверки |
|---|---|---|
| Прием темы, вопросы, гипотезы | `bot.py`, `models.py`, `orchestrator.py` | Тема и ТЗ подтверждаются командами |
| Discovery и итеративные вопросы | `prompts.py`, `bot.py` | 5 обязательных и максимум 3 дополнительных вопроса |
| Semantic Scholar API | `retriever.py`, LangChain StructuredTool | Реальные метаданные; при 429 провайдер может быть недоступен |
| arXiv API и PDF | `retriever.py`, Atom + pypdf | PDF только с arXiv, лимит размера/страниц, fallback на аннотации |
| Актуальные публикации за 5 лет | Фильтр года и submittedDate | 5 календарных лет; точная дата публикации в Semantic Scholar не всегда предоставлена |
| Систематизация и сравнение подходов | Analyzer и LLM-критик | Автоматический синтез по доступным свидетельствам; экспертное качество не гарантировано |
| Научная достоверность | Реальные источники, фрагменты, self-check | Происхождение свидетельств проверяется; истинность требует авторской проверки |
| Модульная архитектура | Orchestrator, Retriever, Analyzer, Reporter, Validator | Analyzer представлен узлом графа и отдельным модулем вычислений |
| LangChain и LangGraph | LCEL, StructuredTool, StateGraph | Используется разрешенный заданием LangChain вместо GigaChain |
| ReAct или Plan-and-Execute | Plan-and-Execute | План и последовательный исполнимый граф, без произвольного кода |
| Stateful Memory | SQLite диалог + SqliteSaver checkpoints + журнал проверенных разделов | Восстановление между узлами и разделами при совпадении входных данных/промптов; незавершенный раздел повторяется |
| Embedding model + FAISS/Chroma | Multilingual FastEmbed + FAISS | Локальная embedding-модель вместо платной text-embedding-3-large |
| LLM с большим контекстом | DeepSeek flash, модель конфигурируется | Имя проверено по API; работа делится на разделы и ограниченный RAG-контекст |
| Минимум 15 источников | Validator проверяет уникальный корпус и фактические ссылки в тексте | Число не уменьшается настройкой MIN_SOURCES |
| DOCX или ODT | python-docx, формат DOCX | ODT не реализован: задание разрешает DOCX или ODT |
| PDF с сохранением форматирования | LibreOffice конвертирует тот же DOCX | Выбрана конвертация офисным движком; ReportLab/pandoc не используются в основной конвертации |
| ГОСТ 7.32-2017 | Детерминированный шаблон и автоматический нормоконтроль | Учебный титульный лист, ограниченный профиль; не сертификация официальной НИР |
| ГОСТ 7.1-2003 | Шаблон электронного ресурса из фактических метаданных | Универсальный нормоконтроль библиографии не заявлен |
| Таблицы и графики при необходимости | Статистика CSV, график источников по годам | Только измеренные/метаданные; числовые результаты не придумываются |
| LangSmith | Поддержка через переменные окружения LangChain | Опционален; без пользовательского ключа во время разработки не включался |
| Telegram | python-telegram-bot, long polling | Личные чаты, owner/allowlist, доступный работающий процесс |
| Документация | README, матрица, отчет | Содержит запуск, команды, пределы и диагностику |

Параметры «полная научная достоверность» и «любая работа строго по всему ГОСТ» не могут быть честно подтверждены лишь программными тестами. Реализация блокирует конкретные обнаруживаемые нарушения и предоставляет журнал свидетельств для проверки человеком.
